## 0. Kurzfassung

1. **Kein Beleg für Session-Kicks zwischen App und Drittclient.** Niemand berichtet „already logged in“ oder ein Rauswerfen der App durch HA/ioBroker. Maintainer beider Ökosysteme sagen, App/Portal und Cloud-Adapter laufen parallel. Was es gibt: **IP-basierte Sperren** – wenn ein Client zu oft **authentifiziert** oder falsch pollt, sind Portal *und* App von derselben öffentlichen IP blockiert, während die Anlage selbst online bleibt. Gegenmittel in allen Berichten: neue öffentliche IP oder warten.
2. **Rate-Limits sind real, aber undokumentiert.** Der einzige „offizielle“ Zahlenwert ist `MaxSystemBusSamplingRateSec: 60` aus `CurrentUserLoadDataSlim` (ioBroker-Log). Wolf hat am 2024-03-14 den Passwort-Login-Flow „wegen extrem hoher Login-Request-Zahlen“ abgeschaltet und OAuth (PKCE) verpflichtend gemacht. Beobachtete Sperren: 429 auf `/idsrv/.well-known/openid-configuration`, 400 beim Login, Portal-Login-Seite ohne Formular; Dauer laut Nutzern „einige Minuten“ bis „~1 h“, laut openHAB-Maintainer auch tagelang.
3. **Schreiben funktioniert technisch** (ioBroker seit 2021, wolf-comm `write_value` seit 0.0.15/0.0.16 Okt. 2024). Belastbare Nutzerberichte mit wolf-comm/heatwrite/wolflink-write gibt es **nicht** (0 Issues); nur Autoren-Aussagen. Aus ioBroker: Schreiben scheitert, wenn `ack=true` gesetzt wird; API liefert Min/Max-Grenzen, die den Wertebereich beschneiden; zu häufiges Schreiben eines Werts führte zu Verbindungssperren (ein Nutzer). `IsReadOnly` kommt aus `GetGuiDescriptionForGateway`; EEPROM-Verschleiß ist nur eine Behauptung des heatwrite-Autors ohne Wolf-Quelle.
4. **Auth-Historie:** Jan 2023 erster OpenID-Umstieg (nach 1,5 Tagen zurückgerollt), Feb 2024 endgültiger Umstieg → neue Lib `wolf-comm`, März 2024 Passwort-Flow abgeschaltet + IP-Sperren → Token-Reuse/UpdateSession-Fix (wolf-comm 0.0.7, HA 2024.5), Juni 2026 Payload-Änderung (`SystemShareId`) → wolf-comm 0.0.52 + HA-Hub-Modell. Es gibt **keinen Hinweis auf `id.wolf.eu`**; alle Quellen nutzen `www.wolf-smartset.com/idsrv` (IdentityServer4, Client-ID `smartset.web`).
5. **Offiziell:** Wolf-Dev-Team: „We have the instruction of not working for unofficial products“ (2024-03-14). Wolf-Support per Mail an einen HA-Nutzer (2026-01): Anbindung von Home Assistant/Drittanbietern „nicht geplant“, „wird vorerst nicht unterstützt“. Im Feb 2026 half dasselbe Dev-Team aber dem lokalen Projekt ism7mqtt bei Firmware-5-Kompatibilität. Nutzungsbedingungen des Smartset-Portals: **nicht gefunden**.

## 1. Parallele Sessions (App + HA + weitere Integration, gleicher Account)

### Verifizierte Fakten (Code / Maintainer)

- **wolf-comm (HA):** Jede `WolfClient`-Instanz macht einen eigenen OAuth-Login (`/idsrv/Account/Login` → `/idsrv/connect/token`) und erzeugt eine eigene Portal-Session (`POST api/portal/CreateSession2` → `BrowserSessionId`), die alle 60 s per `POST api/portal/UpdateSession` verlängert wird. Kein Token-Sharing zwischen Instanzen, kein Refresh-Token („No refresh token is used. When the token expires the whole flow is re-run“). [Code] https://github.com/janrothkegel/wolf-comm/blob/master/wolf_comm/wolf_client.py , https://github.com/janrothkegel/wolf-comm/blob/master/wolf_comm/create_session.py , https://github.com/janrothkegel/wolf-comm/blob/master/CLAUDE.md (abgerufen 2026-10-14)
- **HA wolflink** pollt alle 60 s (`update_interval=timedelta(seconds=60)`). [Code] https://github.com/home-assistant/core/blob/dev/homeassistant/components/wolflink/coordinator.py (2026-10-14)
- **ioBroker README:** „This is not a local connection. The benefit is that you can use the Wolf Smartset app or Wolf Smartset Portal and also receive or set param values in ioBroker in parallel.“ [Maintainer] https://github.com/iobroker-community-adapters/ioBroker.wolf-smartset#readme (2026-10-14)
- **ioBroker README, IP-Bindung:** „The Wolf Smartset server is Client IP address aware. This means, it associates some application state information with the public IP address of the client application.“ Expertenmodus: „Tests showed, that it was quite hard to leave the Expert level once you enabled it. [...] only a change of the adapter's public IP address in combination with an adapter instance reload might get the adapter back to User level.“ Nebenwirkung: „In Expert mode some pre-period statistics might not be updated reliably from Wolf Smartset server!“ [Maintainer] (gleiche URL)

## 2. Rate-Limits / Throttling / Sperren

### Verifizierte Fakten (Code / Maintainer)

Adapter warnt, wenn `pollIntervalShort < MaxSystemBusSamplingRateSec`: „is less than min poll interval (… s) permitted by Wolf“.
